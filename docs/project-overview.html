PAYRDR Payment SDK

Android SDK for secure payment processing with card tokenization, UI forms, Google Pay, and 3DS support.

Kotlin Android Gradle KTS minSdk 21 targetSdk 35

The PAYRDR Payment SDK is a modular Android library for integrating payment processing into mobile applications. It provides three levels of integration:

  • Full payment flow (sdk_payment) — complete checkout with UI, 3DS, and backend communication
  • Form-based cryptogram (sdk_forms) — payment UI components with cryptogram generation
  • Token generation (sdk_core) — low-level RSA encryption of card data

SDK Modules

sdk_core — Cryptography & Token Generation
sdk_core/src/main/kotlin/net/payrdr/mobile/payment/sdk/core/

The foundation module responsible for encrypting card data into payment tokens using RSA cryptography. It has no UI dependencies and can be used standalone for custom payment form implementations.

Public API

val sdkCore = SDKCore(context)

val params = CardParams(
    mdOrder = "order-12345",
    pan = "4111111111111111",
    cvc = "123",
    expiryMMYY = "1225",
    cardHolder = "JOHN DOE",
    pubKey = "-----BEGIN PUBLIC KEY-----..."
)

val config = SDKCoreConfig(params)
val result: TokenResult = sdkCore.generateWithConfig(config)

// result.token  - encrypted payment token
// result.errors - validation error map (if any)

Key Classes

ClassPurpose
SDKCoreMain entry point. Validates input, generates encrypted token.
CardParamsNew card payment data (PAN, CVC, expiry, cardholder, order, public key).
BindingParamsStored/bound card payment data (binding ID, CVC, public key, order).
SDKCoreConfigConfiguration wrapper with timestamp and source tracking.
TokenResultResult object containing either encrypted token or validation errors.

Validation

All card data is validated before encryption:

ValidatorWhat It Checks
CardNumberValidatorPAN format + Luhn algorithm check
CardExpiryValidatorExpiry date format and not expired
CardCodeValidatorCVC/CVV length (3-4 digits)
CardHolderValidatorCardholder name format
OrderNumberValidatorOrder ID format
PubKeyValidatorRSA public key validity

Cryptography

RSACryptogramCipher encrypts the payment string using the merchant's RSA public key. The payment string is assembled by PaymentStringProcessor from card data, a timestamp, and a UUID. The result is encoded with Base58Coder.

Depends on: sdk_logs
sdk_forms — UI Components & Payment Forms
sdk_forms/src/main/kotlin/net/payrdr/mobile/payment/sdk/form/

Provides ready-to-use payment form UI: card entry screens, saved card selection, Google Pay integration, NFC/camera scanning, and multi-language support. Handles cryptogram generation internally using sdk_core.

Public API

// Initialize
SDKForms.init(SDKConfig(keyProvider, cardInfoProvider))

// Launch payment form
val config = PaymentConfigBuilder(order, cards)
    .cardSaveOptions(CardSaveOptions.YES_BY_DEFAULT)
    .cameraScannerOptions(CameraScannerOptions.ENABLED)
    .locale(Locales.EN)
    .build()

SDKForms.cryptogram(activity, config)

// Handle result
SDKForms.handleCryptogramResult(requestCode, data,
    object : ResultCryptogramCallback<CryptogramData> {
        override fun onSuccess(result: CryptogramData) {
            // result.status, result.paymentInfo
        }
        override fun onFail(e: SDKException) { }
    }
)

Key Classes

SDKFormsMain entry point (singleton). Init, launch forms, handle results.

CryptogramDataResult with status, payment info, and deleted cards list.

sdk_payment — Payment Flow Orchestration
sdk_payment/src/main/kotlin/net/payrdr/mobile/payment/sdk/

The highest-level module that orchestrates the entire payment process: fetches order status, displays appropriate UI via sdk_forms, generates cryptograms via sdk_core, communicates with the payment backend, and handles 3DS challenges.

Public API

// Initialize with backend URL
SDKPayment.init(SDKPaymentConfig(
    baseURL = "https://gateway.example.com",
    sslContextConfig = sslContextConfig  // optional custom CA
))

// Start checkout by order ID
SDKPayment.checkout(activity, CheckoutConfig.MdOrder("order-12345"))

// Or by session ID
SDKPayment.checkout(activity, CheckoutConfig.SessionId("session-abc"))

// Handle result
SDKPayment.handleCheckoutResult(requestCode, data,
    object : ResultPaymentCallback<PaymentResult> {
        override fun onResult(result: PaymentResult) {
            // result.isSuccess, result.exception, result.sessionId
        }
    }
)

Key Classes

ClassPurpose
SDKPaymentMain entry point (singleton). Init, checkout, handle results.
SDKPaymentConfigConfiguration with base URL and optional SSL config.
CheckoutConfigSealed class: MdOrder(value) or SessionId(value).
PaymentResultFinal result (sessionId, isSuccess, exception).
PaymentActivityInternal activity managing the full payment flow.

sdk_logs — Logging & Analytics
sdk_logs/src/main/kotlin/net/payrdr/mobile/payment/sdk/logs/

Centralized logging module used by all other SDK modules. Provides a pluggable logging interface with built-in Sentry integration for error tracking and log upload.

Public API

// Add a custom log handler
Logger.addLogInterface(myCustomLogger)

// Log messages at different levels
Logger.debug("ClassName.method", "TAG", "Debug message")
Logger.info("ClassName.method", "TAG", "Info message")
Logger.warning("ClassName.method", "TAG", "Warning", exception)
Logger.error("ClassName.method", "TAG", "Error", exception)

// Upload collected logs
Logger.uploadLogs()

Key Classes

ClassPurpose
LoggerSingleton facade for all logging operations.
LogInterfaceInterface for custom log implementations.
SentryLoggerBuilt-in Sentry integration for error tracking.
LogUploaderAbstract interface for log upload.
SentryLogUploaderSentry-based log uploader implementation.

No dependencies — this is the base module.

Payment Flows

Full Payment Flow (SDKPayment)

The complete checkout flow from app initialization to payment result. This is the recommended integration path.

sequenceDiagram participant App participant SDKPayment participant PaymentApi participant SDKForms participant SDKCore participant Backend participant 3DS App->>SDKPayment: init(SDKPaymentConfig) App->>SDKPayment: checkout(activity, CheckoutConfig) SDKPayment->>PaymentApi: getSessionStatus(mdOrder) PaymentApi->>Backend: HTTP GET session status Backend-->>PaymentApi: SessionStatusResponse PaymentApi-->>SDKPayment: Order info + saved cards alt Has saved cards SDKPayment->>SDKForms: Show CardListActivity else No saved cards SDKPayment->>SDKForms: Show CardNewActivity end SDKForms-->>SDKPayment: User selects/enters card SDKPayment->>SDKCore: Generate cryptogram SDKCore->>SDKCore: Validate fields SDKCore->>SDKCore: RSA encrypt card data SDKCore-->>SDKPayment: TokenResult (encrypted token) SDKPayment->>PaymentApi: processForm(cryptogram) PaymentApi->>Backend: HTTP POST payment Backend-->>PaymentApi: ProcessFormResponse alt 3DS Required SDKPayment->>3DS: Show 3DS challenge (WebView) 3DS-->>SDKPayment: Challenge result SDKPayment->>PaymentApi: finish3dsVer2Payment end SDKPayment->>PaymentApi: getFinishedPaymentInfo PaymentApi-->>SDKPayment: Final status SDKPayment-->>App: PaymentResult (success/failure)

Token Generation Flow (SDKCore)

Direct token generation for apps that provide their own UI. Minimal integration with no network calls.

sequenceDiagram participant App participant SDKCore participant Validators participant Cipher App->>SDKCore: generateWithConfig(SDKCoreConfig) SDKCore->>Validators: Validate all fields alt Validation fails Validators-->>SDKCore: Error map SDKCore-->>App: TokenResult(errors) else Validation passes Validators-->>SDKCore: OK SDKCore->>SDKCore: Build CardInfo SDKCore->>SDKCore: PaymentStringProcessor.create() SDKCore->>Cipher: RSACryptogramCipher.encode(paymentString, pubKey) Cipher-->>SDKCore: Encrypted token (Base58) SDKCore-->>App: TokenResult(token) end

Sample Applications

app_kotlin_ui — Full Payment Flow Demo
app_kotlin_ui/src/main/kotlin/net/payrdr/mobile/payment/sample/kotlin/

Comprehensive demo showing the complete SDKPayment integration. Demonstrates:

  • Full checkout flow with SDKPayment.checkout()
